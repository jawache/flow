# Upgrade to 0.1.0

From a checkout linked with `npm link` · 2026-09-15 · [all guides](./index.md)

0.1.0 is the first release published to npm. Before it, a repo ran flow from a clone of the flow repository, linked with `npm link`. This page moves a repo from such a checkout to the published package, and covers what changed in the packs before the release: the `guard` pack is renamed `flow`, some checks left `@jawache/flow/packs`, and some pack entries were removed or renamed. The hook registrations, `.githooks/pre-commit` and the CLI commands are the same as in the checkout.

## 1 · Install 0.1.0

Replace the link with the published package. Keep `flow` on PATH: the hook registrations and `.githooks/pre-commit` run it by name.

```sh
npm unlink -g @jawache/flow
npm i -g @jawache/flow@0.1.0    # puts `flow` on PATH
npm i -D @jawache/flow@0.1.0    # in a repo with a package.json: pins the version in its lockfile
```

Commit `package.json` and the lockfile together. If the repo binds the `node` pack, the commit message needs a line `new-dep: @jawache/flow — <why>`, or `node.newDependencyNeedsReason` refuses the commit.

`flow status` does not check that `flow` is on PATH. Without it, the session hooks fail with nothing blocked, and `.githooks/pre-commit` refuses every commit.

## 2 · Required changes

### 2.1 · Rename the `guard` pack to `flow`

**Applies if:** `grep -rnE '\bguard\b' flow.config.ts` (and your own pack files) prints an import or a binding of `guard`. After the install, `flow status` exits 2 with `does not provide an export named 'guard'`.

**Change:**

```ts
// before
import { guard } from "@jawache/flow/packs";
pack(guard, { packs: ["./guards/house.ts"] })
override(guard.someEntry)
// after
import { flow } from "@jawache/flow/packs";
pack(flow, { packs: ["./guards/house.ts"] })
override(flow.someEntry)
```

`packs` is required. `[]` is a valid value. Leaving it out refuses with `missing-parameter`.

**Why:** the pack that protects the guard itself is named after the product.

### 2.2 · Replace checks removed from `@jawache/flow/packs`

**Applies if:** this prints a line:

```sh
grep -rnE 'conventionalCommit|noGitDiscard|noHandEditedVersion|justfileDocs|lockfileInStep|newCommandNeedsCaller|\bSurface\b' flow.config.ts <your pack files>
```

**Change:** for `conventionalCommit`, `noGitDiscard` and `noHandEditedVersion`, bind the `git` pack. For `justfileDocs`, bind the `justfile` pack. For `lockfileInStep`, bind the `node` pack. Each pack includes the rule. To keep a rule without its pack, copy the check into your own pack.

Replace `newCommandNeedsCaller` with `commitReason` from `@jawache/flow`. Its regex patterns are now listed in the binding, one capture group each:

```ts
// before
newCommandNeedsCaller({ surfaces: [{ file: "flow.ts", known: ["test", "hook"] }], token: "new-verb:" })
// after
commitReason({
  diffAdds: [{ file: "flow.ts", patterns: ['command\\s*===\\s*"([a-z][a-z-]*)"'], known: ["test", "hook"] }],
  token: "new-verb:",
})
```

The old check matched three patterns without listing them: `'case\\s+"([a-z][a-z-]*)"\\s*:'`, `'command\\s*===\\s*"([a-z][a-z-]*)"'` and `'sub\\s*===\\s*"([a-z][a-z-]*)"'`. List the ones your surface uses. A test case that records the diff changes its key from `"git diff HEAD -- flow.ts"` to `"diff HEAD -- 'flow.ts'"`.

**Why:** a check lives in the pack that uses it, or in the grammar when more than one does.

### 2.3 · Remove or rename overrides of entries that are gone

**Applies if:** this prints a line:

```sh
grep -rnE 'override\((fcis\.(noLogicInTypesOrIndex|strictLayout)|typescript\.(tsconfigFromBase|eslintFromBase)|secrets\.dxSeam)' flow.config.ts <your pack files>
```

After the install, `flow status` reports `unknown-entry` and the config does not load.

**Change:**

- `fcis.noLogicInTypesOrIndex`, `fcis.strictLayout` and `secrets.dxSeam` are removed: delete their overrides.
- `typescript.tsconfigFromBase` is now `typescript.tsconfigStrict`: rename the override.
- `typescript.eslintFromBase` exists only when the `typescript` pack is given `eslintBase` (2.4).

### 2.4 · Name your base files to the `typescript` pack

**Applies if:** the repo has a `tsconfig.base.json` or an `eslint.config.base.js` that its other configs extend.

**Change:**

```ts
// before
pack(typescript, { typecheck, lint })
// after
pack(typescript, { typecheck, lint, tsconfigBase: "tsconfig.base.json", eslintBase: "./eslint.config.base.js" })
```

**Why:** the pack no longer assumes base files exist. Without these two settings it does not check that every config extends them.

### 2.5 · Remove `names` from the `secrets` pack

**Applies if:** `pack(secrets, { … names: … })` appears in the config.

**Change:** delete `names:`. It is ignored at run time and is a type error in the editor. `dx` and `encrypt` are now optional and default to dotenvx.

## 3 · What now blocks or passes differently

- **`flow.editingTheGuardrails` is shown for Claude Code settings too:** `.claude/settings.json`, `.claude/settings.local.json`, `.claude/agents/**` and `.claude/skills/**`. Pass `hostSurface: []` to the `flow` pack to turn this off.
- **`git.noGitDiscard` refuses more:** a bare `git checkout <tracked path>` is refused, not only the form with `--`. With `cd X && git …` or `git -C X`, it checks repo `X`.
- **`git.noForcePush` matches only a real command**, so the words in prose or a heredoc no longer trip it.
- **`flow status` exits 2 for every config that does not load.** A config the grammar refused used to exit 1. Check any script that tells the two apart.
- **While the grammar refuses the config, the agent may still write the config and its pack files** to fix it, and the turn can end. Every write used to be refused.
- **A CommonJS repo loads its config.** A `package.json` with `"type": "commonjs"`, or with no `type`, used to fail with `Cannot use import statement outside a module`.
- **`node.dependencies` watches all five lockfiles.**

## 4 · Optional

New pack parameters, all with defaults:

- `docs`: `root`, `allow`
- `tdd`: `tests`
- `fcis`: `sibling`, `tests`
- `git`: `versionFile`, `types`
- `justfile`: `tools`, and `recipes`, which turns on the new `justfile.useTheRecipe` entry
- `secrets`: `publicPrefixes`, `localFiles`, `envFiles`, `extraSecretShapes`
- `typescript`: `strictOptions`

New exports from `@jawache/flow`: `DiffAdds`, `gitDirPrefix`, `escapeRe`, `substitutionInProse` and `SUBSTITUTION_MESSAGE`.

## 5 · Verify

```sh
command -v flow && flow --version    # prints a path, then 0.1.0
flow status                          # green
flow test                            # every case green
flow commit $(git ls-files --cached --others --exclude-standard)    # exit 0
```
