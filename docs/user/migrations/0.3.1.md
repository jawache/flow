# Upgrade to 0.3.1

[All guides](./index.md)

0.3.1 shows a subagent the session breadcrumbs when it starts, tells a session when it works in a git worktree flow does not guard, and refuses the `gh` commands that delete something on GitHub. Every repo re-runs `flow init`, which adds one hook registration. No config changes.

- **A subagent's start.** `flow init` registers Claude Code's `SubagentStart` hook, so a subagent is shown every `session` breadcrumb when it starts.
- **Another worktree.** A tool call that writes or runs in another worktree of the repository passes the agent a message, once per worktree, saying flow does not guard it.
- **`gh`.** `git.noDestructiveGh` refuses `gh repo delete`, `archive` and `rename`, `gh release delete`, and `gh api` with the DELETE method.
- **The commit gate over the whole tree.** `flow hook commit --all` checks a file identical to the one in the last commit for its content, never as an edit.

## 1 · Install 0.3.1

```sh
npm i -D @jawache/flow@0.3.1    # when flow is a dev dependency of the repo
npm i -g @jawache/flow@0.3.1    # when `flow` is installed globally
```

With a dev dependency, type each `flow` command on this page as `npx flow`.

## 2 · Required changes

### 2.1 · Re-run `flow init` to register `SubagentStart`

**Applies if:** `flow status` prints a red `hooks` line that names `SubagentStart`:

```
  ✗ hooks: ~/.claude/settings.json does not call flow for SubagentStart — re-run `flow init`. Until it does, no note is shown when a subagent starts.
```

An init before 0.3.1 wrote six registrations, and `SubagentStart` was not one.

**Change:** run `flow init`. It adds the one registration and keeps every other key in the settings file:

```
flow init — created:
  + ~/.claude/settings.json — SubagentStart
  next: `flow status` — what is bound, and what is not wired yet.
```

The new entry runs the same command as the other six, with `subagent-start` as the event. With flow as a dev dependency, the file is the repo's `.claude/settings.json`: commit it.

**Why:** Claude Code sends `SessionStart` only when the main chat starts. A subagent's start sends `SubagentStart`, and without it a subagent is shown no `session` breadcrumb.

## 3 · What now blocks or passes differently

- **A subagent is shown every `session` breadcrumb when it starts.** In 0.3.0, a subagent was shown none. A breadcrumb bound with `.for(…)` to a category that its brief recognises is shown at the subagent's first tool call instead, once the brief can be read. Claude Code's internal agents, which make prompt suggestions and answer `/btw` side questions, are shown none. See [the session moment](../reference/moments.md).
- **A tool call in another worktree of the repository passes the agent a message.** When the Edit or Write tool writes a file in another worktree, or a shell command runs in one, flow passes the agent a message beside the call's result, once per worktree. The message names the folder flow guards and the worktree it does not, and tells the agent to stop and ask you to start a session there. The call goes through. A subagent started with `isolation: "worktree"` is told the same way. [flow says it does not guard this worktree](../troubleshooting/flow-does-not-guard-this-worktree.md) gives the fix.
- **`git.noDestructiveGh` is new in the `git` pack.** It refuses `gh repo delete`, `gh repo archive`, `gh repo rename`, `gh release delete`, and `gh api` with `-X DELETE` or `--method DELETE` in any letter case. A call that only names those words, such as `gh repo view delete`, is refused too. `gh issue delete`, `gh gist delete` and `gh release delete-asset` pass. If one is refused, run it in your own terminal. A repo that lets sessions run them disables the entry in `flow.config.ts`. The `git` pack's orientation breadcrumb names the refusal.
- **`node.newDependencyNeedsReason` says what it saw.** It fires when `package.json` has changes since the last commit, staged or not, and the commit's message has no `new-dep:` line. The refusal now says so, and says to commit those changes first with their own `new-dep:` line, or stash them. What it refuses is unchanged.
- **`protectedPath` passes a file identical to the one in the last commit.** Only `flow hook commit --all` calls the rule with such a file, so the gate over the whole tree no longer refuses every protected file that is as committed. A check of your own reads this as `ctx.file.unchanged`, which is `true` only under `--all` on such a file. See [ctx.file](../reference/ctx.md#ctxfile).
- **A rewrite that leaves the snapshot is judged.** When one call takes a file out of `snapshotInclude`, or adds it to `.gitignore`, and also rewrites it, the write rules judge the rewrite, and a refused one is put back. In 0.3.0, the rewrite was dropped. A file that enters the snapshot during a call is recorded as it stands and not judged for that call, and the after-call rail prints one line naming it.
- **A call still running after an hour is dead.** It is not counted as overlapping another agent's call, so a refusal in that other call writes back every file under `revert: "all"`, as when no call overlaps. The dead call's snapshot stays for the day, so a call approved after an hour at the prompt is still checked.
- **`flow status` names only a rule that names an ignored path exactly.** A rule with `.on(".env.keys")` on an ignored file still gets a red line, unless `snapshotInclude` lists the path. A broad glob such as `src/**` that also matches an ignored file gets none. In 0.3.0, the broad glob got one too.
- **`flow status` reports a double fire only where both settings files call flow.** An event the repo's own `.claude/settings.json` does not call flow for is a `does not call flow` line, and `flow init` writes the repo's command for it. In 0.3.0, the machine-wide file's command for that event was reported as a double fire.

## 4 · Optional

- **Read the migration guides from the package.** `npm pack` now ships every page under `docs/user/` and `CHANGELOG.md`, so each link in a guide resolves inside `node_modules/@jawache/flow/`.
- **Scope a `session` breadcrumb to a subagent's brief.** A breadcrumb bound with `.for(…)` to a category recognised by the brief is shown to a matching subagent at its first tool call:

  ```
  builderBrief: breadcrumb()
    .at(session)
    .for(builder)
    .text("You are the builder: build exactly the one task you were briefed on."),
  ```

  `builder` is a category from `defineCategory`. [How to let only some agents write](../how-to/let-only-some-agents-write.md) shows one recognised from a subagent's brief.
