# Upgrade to 0.4.0

[All guides](./index.md)

0.4.0 changes where flow judges. Guardrails judge at `commit` and `command`, and hold a turn at `turn-end`. flow no longer judges a write or a delete in the working tree, and never puts a file back. Breadcrumbs are shown when a file changes, not when it is read. flow is installed from GitHub, ships one pack, registers its hooks inside the repo, and runs under Codex as well as Claude Code. Every repo that uses flow has changes to make.

## 1 · Install 0.4.0

flow is no longer published to npm. Install it from GitHub, at the tag:

```sh
npm i -D github:jawache/flow#v0.4.0
```

Type each `flow` command on this page as `npx flow`.

## 2 · Required changes

### 2.1 · Make flow a dev dependency of the repo

**Applies if:** `npm ls @jawache/flow` in the repo prints `(empty)`. The repo then relies on a global install.

**Change:** run the install command in step 1 in the repo. A repo that is not a Node project first runs `npm init -y` and `npm pkg set private=true`, and adds `node_modules/` to `.gitignore`.

**Why:** 0.4.0 has no machine-wide install. Each repo pins its own copy.

### 2.2 · Run `flow init` again

**Applies if:** always.

**Change:** run `npx flow init --harness claude-code`, adding `,codex` if the repo runs Codex. It writes `.githooks/commit-msg` and deletes `.githooks/pre-commit`, keeping any lines in it that are not flow's. Commit both changes, and each registration file it wrote: `.claude/settings.json`, `.codex/hooks.json`. If git runs another folder's hooks, such as husky's, move flow's two lines from that folder's `pre-commit` hook to its `commit-msg` hook, as `flow init` prints.

**Why:** 0.4.0 judges a commit in git's commit-message hook, where git has the message, and no longer uses the hook before a commit. It registers six hooks in the repo's own `.claude/settings.json` in place of seven, and registers Codex's hooks in `.codex/hooks.json` when Codex is named. In a terminal `flow init` prompts for the harnesses, so the flag is for an agent that runs this step.

### 2.3 · Replace the packs flow no longer ships

**Applies if:** `git grep -n "@jawache/flow/packs" -- flow.config.ts guards/` shows an import of `docs`, `fcis`, `git`, `justfile`, `node`, `secrets`, `tdd`, `typescript` or `work`.

**Change:** remove the import and its `pack(…)` and `override(…)` lines. For each rule you still want, write it in a pack of your own in `guards/`, or install a package of packs that has it. Rewrite each rule for the moments below. `flow` is still imported from `@jawache/flow/packs`.

**Why:** flow ships one pack, `flow`. Rules about how you work are yours.

### 2.4 · Bind the `flow` pack with no parameter

**Applies if:** `git grep -n "pack(flow," -- flow.config.ts` prints a line.

**Change:**

```
pack(flow, { packs: ["guards/**"] }),     // before
pack(flow),                               // after
```

To keep your own pack files protected, add a rule of your own:

```
keepGuards: guardrail()
  .at(commit)
  .check(protectedPath({ paths: ["guards/**"], existingOnly: true }))
  .message("A guard file is changed by its owner, not in passing.")
  .test({ pass: [{ staged: ["src/a.ts"] }], block: [{ staged: [], deleted: ["guards/house.ts"] }] }),
```

Remove any `override(flow.editingTheGuardrails)` line: the entry is gone.

**Why:** the pack protects flow's own files, and has three entries: `flow.orientation`, `flow.noUninstall` and `flow.noDeleteGuardrails`.

### 2.5 · Move every rule off `write` and `deletion`

**Applies if:** `git grep -nE "\.at\(.*\b(write|deletion)\b" -- flow.config.ts guards/` prints a line.

**Change:** take `write` and `deletion` out of each import and each `.at(…)`:

```
.at(write, commit)             // before
.at(commit)                    // after

.at(write, deletion, commit)   // before, with protectedPath
.on("src/generated/**")
.check(protectedPath({}))

.at(commit)                    // after: the paths are an option, and there is no .on(…)
.check(protectedPath({ paths: ["src/generated/**"] }))
```

A rule bound only at `write` or `deletion` moves to `.at(commit)`. Its `{ path, content }` cases still run, as a commit of that one file. A rule that cannot be judged at a commit, such as one that stops a write while something else is running, has no moment in 0.4.0: delete it, or make it a breadcrumb.

In a check of your own, a file the commit deletes is no longer passed as `ctx.file` with `ctx.moment` set to `delete`. Read the deleted paths from `ctx.deleted`, a list in every commit call. A case lists them as `deleted: ["path"]`, in place of `deleted: { path: content }`.

**Why:** the `write` and `delete` moments are removed. A commit judges the same content, and every commit rule is given the paths the commit deletes.

### 2.6 · Move every breadcrumb off `touch`

**Applies if:** `git grep -nE "\.at\(.*\btouch\b" -- flow.config.ts guards/` prints a line.

**Change:** replace `touch` with `fileChange`, in the import and in each `.at(…)`. A breadcrumb every agent needs before it starts moves to `.at(session)`.

**Why:** the `touch` moment is removed. A `file-change` breadcrumb is shown after the first change under its globs, and reading a file shows nothing.

### 2.7 · Remove `oneWriter`

**Applies if:** `git grep -n "oneWriter" -- flow.config.ts guards/` prints a line.

**Change:** delete the rule. To stop a type of agent writing files, take the write tools out of that agent's tool list in the harness.

**Why:** the check refused a write and put the file back, and 0.4.0 does neither.

### 2.8 · Remove `substitutionInProse`

**Applies if:** `git grep -nE "substitutionInProse|SUBSTITUTION_MESSAGE" -- flow.config.ts guards/` prints a line.

**Change:** delete the rule and the two imports. To keep the advice, add a line to a `session` breadcrumb: "quote a commit message or a pull request body with single quotes, so the shell runs no backtick in it".

**Why:** the check is removed. A commit message is read from git in 0.4.0, after the shell has run.

### 2.9 · Move commit-message rules from `command` to `commit`

**Applies if:** `git grep -nE "commitReason|commitMessage" -- flow.config.ts guards/` prints a line.

**Change:** bind `commitReason` at `commit`, and give its cases a `message` and a `staged` list in place of a `git commit` command line and the git answers:

```
// before
.at(command)
.test({ block: [{ command: 'git commit -m "feat: x"', world: { exec: { "git diff HEAD --name-only": { stdout: "package.json" }, /* … */ } } }] })

// after
.at(commit)
.test({ block: [{ message: "feat: x", staged: ["package.json"] }] })
```

A `diffAdds` case supplies `"diff --cached -- '<file>'"` in its `world`, in place of `"diff HEAD -- '<file>'"`.

`commitMessage` was a helper that read the message from a command line. It is now a stock check. In a check of your own, read the message from `ctx.message`, at `commit`.

**Why:** git's commit-message hook has the message whole, however the commit was made.

### 2.10 · Remove `revert` and `snapshotInclude`

**Applies if:** `git grep -nE "revert|snapshotInclude" -- flow.config.ts` prints a setting.

**Change:** delete the key from the second argument of `defineConfig`.

**Why:** both configured the snapshot, which is removed. A config that sets either does not load.

### 2.11 · Remove the machine-wide install

**Applies if:** `grep -c "flow hook" ~/.claude/settings.json` prints a number above 0, or `npm ls -g @jawache/flow` lists it. Do this once per machine, after every repo on it is on 0.4.0.

**Change:** in your own terminal, in any repo on 0.4.0:

```sh
npx flow uninstall --machine     # removes this repo's wiring, and flow's hooks from the machine-wide settings file
npm uninstall -g @jawache/flow
```

Then run `npx flow init` in that repo again, to set that repo up again. `.flow/` and its logs are deleted by the uninstall.

**Why:** with both in place, each hook runs twice.

## 3 · What now blocks or passes differently

- **A write is never refused, and never put back.** An edit that breaks a content rule is written to the working tree. The commit that stages it is refused.
- **A delete is never refused before it runs.** A commit that deletes a file under a `protectedPath` rule is refused.
- **Reading a file shows no breadcrumb.**
- **Someone who commits in an editor is refused after writing the message,** not before the editor opens.
- **A commit message is judged however the commit is made:** from an editor, from a file, or by a person. In 0.3 only a message on an agent's command line was read.
- **A merge commit passes,** content and message.
- **A commit in a scratch repo passes.** A commit rule runs only where the repo's own git hooks run.
- **Another worktree of the same repo is guarded** like the one the session started in. The "flow does not guard this worktree" message is gone.
- **`ranSinceEdit` counts a file a shell command changed** as an edit.
- **`flow facts`** no longer reports `shellWrites`, `shell.writes` or `mismatches`.
- **The session log** has no `write` or `mismatch` rows. It has `change` rows, and a breadcrumb's `cause` is `session`, `first` or `drift`.

## 4 · Optional

- **Run under Codex.** `npx flow init --harness claude-code,codex` registers Codex's hooks. Trust the folder in Codex and approve the hooks with `/hooks`. See [flow under Codex](../reference/codex.md).
- **Check the commit message** with the new stock check: [`commitMessage`](../checks/commit-message.md).
- **Check that doc links in code resolve:** [`docLinks`](../checks/doc-links.md).
- **Choose start breadcrumbs by type of agent,** with `.for(…)` on a `session` breadcrumb. See [how to steer with a breadcrumb](../how-to/steer-with-a-breadcrumb.md#for-a-type-of-agent).

```sh
npx flow status               # green
npx flow test                 # every case green
npx flow hook commit --all    # exit 0
```
