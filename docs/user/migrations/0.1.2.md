# Upgrade to 0.1.2

From 0.1.1 · 2026-09-16 · [all guides](./index.md)

0.1.2 refuses a `depcruise` layer written as a regex, and lets a layer leave holes in itself. Only a repo with its own `depcruise` rule is affected: no shipped pack uses `depcruise`. The exports, the hook registrations and `.githooks/pre-commit` are the same as in 0.1.1.

## 1 · Install 0.1.2

```sh
npm i -D @jawache/flow@0.1.2    # when flow is a dev dependency of the repo
npm i -g @jawache/flow@0.1.2    # when `flow` is installed globally
```

## 2 · Required changes

### 2.1 · Rewrite a `depcruise` layer written as a regex

**Applies if:** after the install, `flow status` exits 2 and `flow test` fails, both reporting `bad-check-options` with the layer and the entry. To find them before you install, search the `layers:` of your own `depcruise` rules for an entry that starts with `^`, contains `(?` or `|`, or ends with `$`:

```sh
grep -rnE '"\^|\(\?|\||\$"' flow.config.ts <your pack files>
```

While the config does not load, flow refuses every write except a write that fixes the config.

**Change:** write the layer as globs. A part the layer must leave out goes in `not`:

```ts
// before
layers: { pages: ["^src/pages/(?!app/|admin/)"] }
// after
layers: { pages: { path: ["src/pages/**"], not: ["src/pages/app/**", "src/pages/admin/**"] } }
```

**Why:** a layer is a list of globs. In 0.1.1, a regex was read as literal text, so the fence loaded and reported itself armed but matched no file.

Two more refusals arrive with this: a layer with a `not` list cannot be listed in another layer's `only`, and `not: ["node:*"]` is refused.

## 3 · What now blocks or passes differently

A fence that used to match nothing starts to work once its layers are globs. A commit that crosses it, and passed in 0.1.1, is now refused.

## 4 · Optional

- **Leave holes in a layer** with `{ path: [...], not: [...] }`, the new `Layer` type.
- **Report unusable options from your own check:** `withFaults` and `faultsOf`, exported from `@jawache/flow`, turn a check's own complaint about its options into a load refusal.

## 5 · Verify

```sh
flow status    # green
flow test      # every case green
flow commit $(git ls-files --cached --others --exclude-standard)    # exit 0, or the fence refusals in section 3
```
