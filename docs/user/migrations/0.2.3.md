# Upgrade to 0.2.3

From 0.2.2 · 2026-10-07 · [all guides](./index.md)

0.2.3 widens `git.noAiAttributionInCommits`, the `git` pack's rule against crediting Claude or Anthropic in a commit. It now also reads a commit made with git's own options before `commit`, such as `git -C <dir> commit`. No changes are needed.

## 1 · Install 0.2.3

```sh
npm i -D @jawache/flow@0.2.3    # when flow is a dev dependency of the repo
npm i -g @jawache/flow@0.2.3    # when `flow` is installed globally
```

## 2 · Required changes

None.

## 3 · What now blocks or passes differently

`git.noAiAttributionInCommits` now refuses a commit command that has git options between `git` and `commit` and credits Claude or Anthropic in its message: `git -C <dir> commit …`, `git -c key=value commit …` and `git --git-dir=… commit …`. An agent working in a git worktree often commits with `git -C`, and those commits passed in 0.2.2. If one is now refused, remove the `Co-Authored-By` line, the "Generated with Claude" line or the Claude Code link from the message, and commit again.

## 4 · Optional

- **Bind the `git` pack, if the repo does not.** `git.noAiAttributionInCommits` is in the `git` pack, so a repo that binds only other packs has no rule against the credit line. Add the binding, with the command that cuts a release in your repo:

  ```ts
  pack(git, { release: "just release" }),
  ```

  The `git` pack also checks that every commit header is a Conventional Commits header. If the repo's headers use a type outside the default list, such as `review:`, pass the `types` parameter. It replaces the default list, so list every type the repo uses.

## 5 · Verify

```sh
flow status               # green
flow test                 # every case green
flow hook commit --all    # exit 0
```
