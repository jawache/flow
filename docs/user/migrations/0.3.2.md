# Upgrade to 0.3.2

[All guides](./index.md)

0.3.2 passes a rule only the work done inside the repository, unless the rule is marked `.everywhere()`. A repo whose own command rule must judge a command run in another folder adds that mark. Every other repo needs no change.

0.3.1 was tagged and not published. A repo on 0.3.0 installs 0.3.2, makes the required change on [the 0.3.1 page](./0.3.1.md), then follows this page.

## 1 · Install 0.3.2

```sh
npm i -D @jawache/flow@0.3.2    # when flow is a dev dependency of the repo
npm i -g @jawache/flow@0.3.2    # when `flow` is installed globally
```

With a dev dependency, type each `flow` command on this page as `npx flow`.

## 2 · Required changes

### 2.1 · Mark a rule that judges work outside the repository `.everywhere()`

**Applies if:** a guardrail of your own must refuse a command wherever it runs, or a file wherever it is. Run `git grep -n -B2 -A2 "\.at(command)" -- ':!node_modules' flow.config.ts guards/` and read each rule. A rule about a command that damages something outside this repo, such as a push, a delete on a remote service, or a tool that changes the machine, is one. A rule about this repo's files, commits or recipes is not.

**Change:** add `.everywhere()` after `.at(…)`, and `.for(…)` when the rule has one:

```
noDeployFromAgent: guardrail()
  .at(command)
  .everywhere()
  .check(banCommands({ ban: ["wrangler deploy"] }))
  .message("A deploy is the user's to run, in their own terminal.")
  .test({ pass: ["wrangler dev"], block: ["wrangler deploy"] }),
```

An override never sets it. `override(pack.entry).everywhere()` is not in the grammar, so the pack decides.

**Why:** without the mark, the rule is not passed a command run in a folder outside this repository, such as `cd /tmp/x && wrangler deploy`, and the command runs.

## 3 · What now blocks or passes differently

- **A command run outside the repository passes a rule without `.everywhere()`.** flow follows `cd`, `pushd`, `git -C` and the variables the line sets, and works out the folder each command runs in. A command in a folder git does not name this repository for is not passed to such a rule. `cd /tmp/r && git init && git commit -m init` runs, because `git.conventionalCommitFormat` is not passed the commit. Every worktree of the repository is inside. A folder flow cannot work out, such as after `cd "$(mktemp -d)"`, counts as inside. See [work outside the repository](../explanation/what-the-guard-sees.md#work-outside-the-repository).
- **A file outside the repository passes a file rule without `.everywhere()`,** and a breadcrumb bound to paths is not shown for it.
- **Nine shipped rules are marked `.everywhere()`** and judge the command wherever it runs: `git.noGitDiscard`, `git.noForcePush`, `git.noDestructiveGh`, `flow.noUninstall`, `work.planIsTheParents`, `work.ticksAreTheChilds`, `work.noAgentInboxItems`, `work.noShellSubstitutionInProse` and `work.checkersDoNotWrite`. Each pack page says which of its rules are.
- **A command pointed at this repository from another folder is inside.** `cd /tmp && git --git-dir=/r/.git --work-tree=/r commit --no-verify`, and the same with `GIT_DIR` or `GIT_WORK_TREE` set on the line, is passed to `git.noGateSkip` as this repository's commit, and refused.
- **`git -C <worktree>` reaches another worktree.** A command that names another worktree of the repository with `git -C` passes the agent the message that flow does not guard it, as a `cd` into it did in 0.3.1. See [flow says it does not guard this worktree](../troubleshooting/flow-does-not-guard-this-worktree.md).
- **In a `.test(…)` case, every command and file counts as inside.** A case's command folder is relative to where its line starts, so a block case such as `cd /tmp/x && wrangler deploy` is still passed to the rule under test.

## 4 · Optional

- **Read where a command runs, in a check of your own.** Each entry of `ctx.commands` has `folder`: the absolute folder the command runs in, or `null` when the line does not settle it. In a case, it is relative to where the line starts. See [ctx.commands](../reference/ctx.md#ctxcommands).

## 5 · Verify

```sh
flow status               # green
flow test                 # every case green
flow hook commit --all    # exit 0
```
