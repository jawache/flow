# Upgrade to 0.2.2

From 0.2.1 · 2026-10-07 · [all guides](./index.md)

0.2.2 changes how the commit gate gets its list of files. The pre-commit hook now runs `flow hook commit` and passes nothing, and flow reads from git the files the commit adds, changes and deletes. A rule bound at both `deletion` and `commit` now also runs on each file a commit deletes, and on the old path of a renamed file. `protectedPath({ existingOnly: true })` now treats a file as new when it was not there before the change. One change is required: the line in `.githooks/pre-commit` that runs `flow commit`.

## 1 · Install 0.2.2

```sh
npm i -D @jawache/flow@0.2.2    # when flow is a dev dependency of the repo
npm i -g @jawache/flow@0.2.2    # when `flow` is installed globally
```

`npm ls @jawache/flow` and `npm ls -g @jawache/flow` show which of the two the repo uses. The hook registrations and `.githooks/pre-commit` run the `flow` that is on PATH.

## 2 · Required changes

### 2.1 · Make the pre-commit hook run `flow hook commit`

**Applies if:** `grep -n "flow commit" .githooks/pre-commit` prints a line. After the install, `flow status` also prints:

```text
  ✗ commit-gate: .githooks/pre-commit calls the old `flow commit`, which leaves every deleted file unchecked — replace its `flow commit …` line with `exec flow hook commit`.
```

**Change:** edit the file. Do not delete it: the `flow` pack refuses a delete of `.githooks/pre-commit`. The hook `flow init` wrote before 0.2.2 ends with these lines:

```sh
staged=$(git diff --cached --name-only --diff-filter=ACMR)
[ -z "$staged" ] && exit 0
# shellcheck disable=SC2086
exec flow commit $staged
```

Replace all four with one line:

```sh
exec flow hook commit
```

If the hook runs other commands as well, keep them, and put `exec flow hook commit` last.

**Why:** the old lines pass flow a list that leaves out deleted files, and they exit before flow runs when a commit only deletes files. `flow commit` still works in 0.2.2, so nothing breaks before you make this change, but deletions are not checked until you do.

### 2.2 · Replace any other command that runs `flow commit` with a file list

**Applies if:** `git grep -n "flow commit" -- ':!.githooks/pre-commit'` prints a line, for example a justfile recipe or a CI step.

**Change:** `flow commit <files…>` now ignores its file list and checks the staged changes. A command that checked a list of files on purpose checks the staged changes instead, which is usually fewer files. To check every file in the repo, use `--all`:

```sh
# before
flow commit $(git ls-files --cached --others --exclude-standard)
# after
flow hook commit --all
```

**Why:** git is now the one source of the file list. `flow hook commit` refuses a file list, and `flow commit` ignores one.

## 3 · What now blocks or passes differently

- **A rule bound at both `deletion` and `commit` now runs on each file a commit deletes.** It is called with the file as a delete (`ctx.moment` is `delete`), with the content the last commit has. A rename is a deletion of the old path plus an added file, so the rule runs on the old path. For example, `protectedPath` bound with `.at(write, deletion, commit)` now refuses a commit that deletes or renames a file it protects. In 0.2.1 that commit passed. If a commit is now refused for this, keep the file, or change the rule.
- **A rule bound at `commit` alone is not called with deleted files.** It checks only the files the commit will contain, as before.
- **`protectedPath({ existingOnly: true })` lets a shell command add a new file.** In 0.2.0 and 0.2.1, a new file that a shell command created was reverted with the append-only message. Now it is kept. At commit, a file is new when the last commit does not have it. In 0.2.1, every staged file counted as existing, so a rule bound at `commit` refused every new file.
- **A config that does not load refuses every commit, including one with nothing staged.** The old hook exited before flow ran when nothing was staged.

## 4 · Optional

- **Refuse a deleted or renamed file at commit as well.** Bind an append-only rule at all three moments:

  ```ts
  appendOnly: guardrail()
    .at(write, deletion, commit)
    .on("migrations/**")
    .check(protectedPath({ existingOnly: true }))
    .message("A migration already written is history — add a new one instead.")
    .test({
      pass: [
        { path: "migrations/002.sql", content: "new" },
        { staged: ["migrations/002.sql"], added: ["migrations/002.sql"], world: { fs: { "migrations/002.sql": "new" } } },
      ],
      block: [
        { path: "migrations/001.sql", content: "edited", world: { fs: { "migrations/001.sql": "old" } } },
        { staged: ["migrations/001.sql"], added: [], world: { fs: { "migrations/001.sql": "edited" } } },
        { staged: [], deleted: { "migrations/001.sql": "old" } },
      ],
    }),
  ```

- **Read `ctx.file.existed` in your own checks.** It is `true` or `false` for a change a shell command made, and for a file at commit. See the [`ctx` reference](../02-entry-reference.md#the-ctx-a-check-reads).
- **Test cases accept three new keys:** `existed` on a `{ path, content }` case, and `added` and `deleted` on a `{ staged }` case. See [Cases](../02-entry-reference.md#cases).
- **`flow hook commit --all`** runs the commit gate over every file git lists, tracked or not, as if all of them were staged.

## 5 · Verify

```sh
flow status               # green, with: ✓ commit-gate: .githooks/pre-commit runs `flow hook commit` over the staged changes
flow test                 # every case green
flow hook commit --all    # exit 0, or only the refusals section 3 describes
```
